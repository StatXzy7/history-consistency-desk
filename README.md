# 寄存器线性一致性分析器（Register Linearizability Analyzer）

一个用于分析**并发错误**的 Windows 桌面工具：判断对一个初值为零的整数寄存器的真实调用历史，
能否解释为一个符合顺序规范的**原子操作序列**（线性一致性）。

- **read**：读取并返回当前值；
- **add d**：原子执行 `x := x + d` 并返回新值；
- **cas expected desired**：当且仅当 `x == expected` 时置为 `desired`，返回是否成功。

范围严格限定为**单对象、最多 16 个调用**，不做通用验证平台。

## 判定语义

- 每次调用的线性化点必须落在它的**调用事件与返回事件之间**；
- **区间不重叠**的调用必须保持真实先后；**区间重叠**的调用允许按任意满足规范的顺序解释
  ——既不是只按开始时间排序，也不是只按返回时间排序；
- **已返回调用不能丢弃**，其返回值必须与规范相符；
- **未返回调用**可以忽略，也可以在解释中按规范补全；
- 能解释时给出一个**具体合法顺序及逐步寄存器值**；不能解释时展示**冲突操作与原因**
  （不保证最小反例）；
- 搜索有**预算**（访问节点数）。预算耗尽时结论为**“未判定”**，绝不会把“没搜完”当作“不存在解释”；
- 枚举过程确定、无随机源，**同一输入结论可重复**。

> 重复编号、返回早于调用、返回类型错误等属于**输入非法**，在解析阶段单独报告，
> 不会与“不一致”混为一谈。

## 构建与运行

环境：JDK 17、Maven 3.9（仅 JUnit 5 一个测试依赖）。

```bash
mvn test       # 运行全部自动化测试
mvn package    # 产物 target/app.jar
java -jar target/app.jar                 # 启动 Swing 界面
java -jar target/app.jar --cli [历史文件]  # 无界面运行（核心可脱离界面）
```

CLI 退出码：`0` 可解释；`2` 不可解释；`3` 输入非法；`4` 预算耗尽未判定。
不给文件路径时从标准输入读取；可用 `--budget N` 调整预算。

## 输入格式

每行一条记录，`#` 起为注释：

```
<事件序号> INVOKE <客户端> <操作编号> read
<事件序号> INVOKE <客户端> <操作编号> add <整数增量>
<事件序号> INVOKE <客户端> <操作编号> cas <期望值> <目标值>
<事件序号> RETURN <客户端> <操作编号> <整数 | true | false>
```

示例见 [`samples/`](samples/)：正确交错、丢失更新、CAS 竞争、未返回调用。

## 界面

- 各客户端一行的**时间线**：色条为调用区间，红色阴影为重叠区间，圆点数字为候选顺序位置；
- 点击任意操作查看其**约束**（必须先于它的调用、可与之重排的重叠调用、候选顺序中的位置）；
- 结论区给出合法顺序/逐步寄存器值，或冲突操作与原因；
- 内置样例下拉框可一键载入：正确交错、丢失更新、CAS 竞争、未返回调用。

## 分析算法

Wing–Gong 风格的状态空间搜索：状态为（剩余调用集合，当前寄存器值），
仅当某调用的全部非重叠前序都已安排时才可安排它；对失败状态记忆化剪枝；
未返回调用同时尝试“补全安排”和“整体忽略”两个分支。核心在 `com.reglinearity.core`，
不依赖 Swing，可独立复用。

## 测试

`mvn test` 共 50+ 个 JUnit 5 用例。其中 `PermutationOracleTest` 使用**独立实现的全排列枚举**
（独立生成历史、独立重算区间关系、独立抄写规范、枚举全部保持先后关系的排列）
与分析器结论交叉核对，覆盖：正常顺序、重叠竞争、未返回调用，以及数千个固定随机种子的
全重叠/随机合法事件词/严格顺序历史和一个 k=2 结果域穷举网格。另含非法记录、
预算耗尽（未判定≠不一致）与结论可重复性的专项测试。
